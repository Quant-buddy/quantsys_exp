# 第一个月 MVP 冲刺任务书

版本：v1.0
适用团队：1 名出资人 + 最多 6 名核心成员的小型量化团队  
系统方向：不做日内、不做高频，以日频波段交易为主，看长做短，高抛低吸  
数据边界：一期只依赖 AKShare、pytdx、交易所/巨潮等免费公开数据源  

---

## 1. 文档目的

本文件用于指导第一个月的 Minimum Viable Product，也就是 MVP 冲刺。

第一个月的核心目的不是追求策略收益最大化，也不是搭建完整机构级量化平台，而是验证团队能否在免费数据源条件下跑通一条最小但完整的量化系统主链路：

```text
免费数据采集
-> 数据清洗与质检
-> 日频因子生成
-> 标签生成
-> 简单策略回测
-> 组合生成
-> 风控过滤
-> T+1 计划单
-> 影子持仓与日报
```

第一个月结束时，团队必须能够回答：

```text
这套系统是否可以从原始免费数据出发，稳定生成一个可解释、可复现、可风控的明日计划单？
```

---

## 2. 第一个月 MVP 总目标

第 30 天前，完成一个可运行的最小量化系统，至少具备以下能力：

1. 拉取 A 股基础股票列表。
2. 拉取交易日历。
3. 拉取最近至少 3 年日线行情。
4. 处理前复权行情。
5. 拉取主要指数行情。
6. 标记 ST、停牌、涨停、跌停、上市天数。
7. 生成至少 10 个核心日频波段因子。
8. 生成 10 日和 20 日未来收益标签。
9. 跑通一个简单 TopN 等权策略回测。
10. 支持手续费、滑点、涨跌停、停牌、100 股整数等基础交易规则。
11. 生成组合目标权重。
12. 生成 T+1 计划单 CSV/Excel。
13. 输出回测报告和每日运行报告。
14. 关键结果支持 run_id 追踪和复现。

## 4. 主链路定义

第一个月所有任务都必须服务于以下主链路：

```text
T 日收盘后
-> 更新股票、日历、行情、状态、指数、财务、行业数据
-> 运行数据质量检查
-> 生成 T 日可用因子
-> 生成股票池
-> 生成打分和排名
-> 生成目标组合
-> 执行风控检查
-> 生成 T+1 计划单
-> 模拟成交
-> 更新影子持仓
-> 输出日报
```

任何不能服务于这条主链路的任务，第一个月先不做。

## 6. 工程规范

第一个月必须建立以下工程规范：

1. 所有生产任务必须可以命令行运行。
2. 所有关键任务必须生成 run_id。
3. 所有关键输出必须能通过 run_id 追踪。
4. 配置参数必须放在 configs，不允许散落硬编码。
5. notebook 只用于研究分析，不允许作为生产任务。
6. 数据表必须保留 source、run_id、update_time 等追踪字段。
7. 计划单必须包含交易理由、风控状态、风控拦截原因。
8. 异常情况下默认不交易。
9. 每日任务失败必须有日志和错误原因。
10. 回测逻辑和每日计划单逻辑必须尽量共用代码。

建议命令形式：

```bash
python jobs/daily_after_close.py --trade-date 2026-07-07
python jobs/build_factors.py --start 2023-01-01 --end 2026-07-07
python jobs/run_backtest.py --start 2023-01-01 --end 2026-06-30
python jobs/generate_order_plan.py --trade-date 2026-07-07
```

## 9. 数据工程师任务

### 9.1 工作内容

数据工程师负责把免费数据源变成可复跑、可检查、可追踪的本地数据底座。

### 9.2 必须交付的数据表

```text
dim_stock
dim_trade_calendar
fact_daily_bar
fact_index_daily_bar
fact_stock_status
fact_industry_member
fact_financial_indicator
quality_report
```

### 9.3 具体任务

| 编号 | 任务 | 产物 | 验收标准 |
|---|---|---|---|
| DE-01 | 股票列表采集 | dim_stock | 包含 symbol、exchange、stock_name、list_date、is_active |
| DE-02 | 交易日历采集 | dim_trade_calendar | 能判断交易日、上一交易日、下一交易日 |
| DE-03 | 日线行情采集 | fact_daily_bar | 最近 3 年 A 股日线覆盖率 >= 99% |
| DE-04 | 前复权处理 | fact_daily_bar.adj_factor 或复权字段 | 复权收益无明显异常跳点 |
| DE-05 | 指数行情采集 | fact_index_daily_bar | 至少包含沪深300、中证500、中证1000、上证指数 |
| DE-06 | ST 状态识别 | fact_stock_status.is_st | 能按日期识别 ST 和 *ST |
| DE-07 | 停牌状态识别 | fact_stock_status.is_suspended | 停牌日不参与交易 |
| DE-08 | 涨跌停状态计算 | fact_stock_status.is_limit_up/is_limit_down | 涨停不买、跌停不卖 |
| DE-09 | 上市天数计算 | fact_stock_status.listed_days | 上市不足 120 日可过滤 |
| DE-10 | 数据质量报告 | quality_report | 每日输出覆盖率、缺失、异常、失败原因 |

### 9.4 数据质量检查

第一个月至少实现以下检查：

```text
交易日历是否存在
日线覆盖率是否 >= 99%
OHLC 是否合法，即 high >= open/close/low，low <= open/close/high
成交量和成交额是否非负
是否出现非涨跌停原因的异常大涨跌
复权价格是否异常
ST、停牌、涨跌停状态是否缺失
AKShare 与 pytdx 抽样收盘价差异是否过大
```

### 9.5 月底验收

随机抽取：

```text
10 个交易日
20 只股票
4 个指数
```

检查行情、复权、状态、停牌、涨跌停是否可复现。

## 10. 量化研究员任务

### 10.1 工作内容

量化研究员负责把“看长做短、高抛低吸、波段交易”的思想转化成可计算的因子、标签和规则。

### 10.2 第一批核心因子

第一个月建议先做 10-20 个核心因子。

中期趋势：

```text
ret_20d
ret_60d
ma_gap_20d
ma_gap_60d
ma_slope_20d
ma_slope_60d
```

短期回撤：

```text
ret_3d
ret_5d
ret_10d
pullback_5d
pullback_10d
price_to_ma20
```

反弹与高抛：

```text
rebound_3d
rebound_5d
rsi_6d
rsi_14d
```

风险波动：

```text
volatility_20d
max_drawdown_20d
atr_20d
```

流动性：

```text
amount_ma_20d
turnover_20d
```

### 10.3 具体任务

| 编号 | 任务 | 产物 | 验收标准 |
|---|---|---|---|
| QR-01 | 定义股票池过滤规则 | stock_pool_rule.md | 明确 ST、停牌、新股、低流动性、涨跌停过滤 |
| QR-02 | 定义第一批因子 | factor_spec_v1.md | 每个因子有公式、窗口、输入字段、缺失处理 |
| QR-03 | 定义标签 | label_spec_v1.md | forward_return_10d/20d 从 T+1 开始计算 |
| QR-04 | 定义第一版选股规则 | strategy_rule_v1.md | 能根据因子生成 TopN 排名 |
| QR-05 | 做因子初步分析 | factor_report_v1.md | 有覆盖率、分布、IC 或分层收益 |
| QR-06 | 检查未来函数风险 | no_lookahead_check.md | 明确每类数据在 T 日是否可得 |

### 10.4 第一版选股规则建议

候选条件示例：

```text
ret_60d > 0
ma_slope_20d > 0
price_to_ma20 < 0
amount_ma_20d > 3000 万
非 ST
非停牌
上市超过 120 个交易日
非涨停买入
非跌停卖出
```

综合分示例：

```text
score = 0.4 * 中期趋势分
      + 0.3 * 回撤低吸分
      + 0.2 * 流动性分
      - 0.1 * 波动风险分
```

## 16. 每日运行 SOP 草案

每日收盘后执行：

```text
1. 更新交易日历和股票列表。
2. 更新日线行情、指数行情、复权信息。
3. 更新 ST、停牌、涨跌停、上市天数。
4. 更新基础财务和行业分类。
5. 运行数据质量检查。
6. 如果核心数据质检失败，停止生成计划单。
7. 生成当日因子。
8. 生成股票池。
9. 生成打分和排名。
10. 生成目标组合。
11. 执行风控检查。
12. 生成 T+1 计划单。
13. 运行模拟成交。
14. 更新影子持仓。
15. 输出日报。
16. 记录异常和处理人。
```

## 19. 风险与应对

| 风险 | 表现 | 应对 |
|---|---|---|
| 免费数据不稳定 | 接口变化、缺字段、缺历史 | 双源抽样校验，核心数据失败则不交易 |
| 范围失控 | 每个人都在做增强项 | 技术负责人冻结 MVP 范围 |
| 未来函数 | 回测很好，实盘失效 | 所有字段检查 T 日是否可得 |
| 回测和实盘不一致 | 回测能跑，计划单不能用 | 回测和计划单共用组合/风控逻辑 |
| 数据质量差 | 缺失、复权异常、停牌误判 | 质检失败时阻断计划单 |
| 文档缺失 | 新人无法复跑 | 每个模块必须有产物和验收说明 |
| 只研究不落地 | notebook 很多，系统没有 | notebook 不允许进入生产链路 |

## 20. 第一个月完成定义

第一个月 MVP 不是代码写完就算完成，而是满足以下条件：

```text
1. 任意指定一个历史交易日，可以从原始数据复跑到计划单。
2. 最近 3 年日线数据可复跑。
3. 至少 10 个核心因子可生成并可解释。
4. 一个简单 TopN 策略可以完成回测。
5. 回测支持基础交易成本和交易限制。
6. 每日收盘后可以生成 T+1 计划单。
7. 计划单包含风控状态和交易理由。
8. 数据异常时默认不生成计划单。
9. 所有关键产物可通过 run_id 追踪。
10. 有每日运行 SOP。
```

只有满足以上条件，团队才建议进入第二个月：

```text
因子扩展
LightGBM baseline
更完整回测
影子实盘稳定运行
事件/公告可选辅助
```

## 22. 结论

第一个月的 MVP 冲刺任务必须形成文档并持续更新。

这份文档不是静态方案，而是技术负责人管理团队的执行工具：

```text
用它控范围
用它派任务
用它做周会
用它验收产物
用它判断是否进入第二个月
```

第一个月最重要的结果不是策略赚多少钱，而是证明：

```text
系统能从免费数据出发，稳定、可复现、可解释、可风控地生成明日计划单。
```
