# 项目代码规范

版本：v0.1  
适用阶段：第 1 个月 MVP 冲刺  
适用范围：`src/`、`jobs/`、`configs/`、`tests/`、`sql/`、`docs/`

## 1. 总原则

第一个月代码规范只服务一个目标：让主链路可运行、可复现、可追踪。

所有代码必须满足：

```text
生产任务可命令行运行
关键输出带 run_id
配置参数不硬编码
异常时默认不交易
结果可被下游岗位复用
```

## 2. 目录职责

| 目录 | 职责 |
|---|---|
| `src/common/` | 公共路径、日期、run_id、日志、配置读取。 |
| `src/data_ingest/` | 数据采集、字段标准化、原始数据到 clean 数据转换。 |
| `src/data_quality/` | 数据质量检查和阻断规则。 |
| `src/factors/` | 因子计算逻辑。 |
| `src/labels/` | 标签生成逻辑。 |
| `src/backtest/` | 回测框架和绩效统计。 |
| `src/portfolio/` | 目标组合生成。 |
| `src/risk/` | 风控过滤和拦截原因。 |
| `src/trading/` | 计划单、模拟成交、影子持仓。 |
| `jobs/` | 可命令行运行的任务入口。 |
| `configs/` | 数据源、模型、组合、风控参数。 |
| `tests/` | 单元测试和主链路冒烟测试。 |

## 3. Python 规范

使用 Python 3.10+。

命名规则：

```text
文件名、函数名、变量名：snake_case
类名：PascalCase
常量：UPPER_SNAKE_CASE
布尔字段：is_ / has_ / should_ 开头
```

函数要求：

```text
单个函数只做一类事情
输入输出字段在 docstring 或调用处说明
不要在库函数里直接写死路径
不要在库函数里静默吞异常
```

生产代码禁止依赖 notebook。notebook 只允许用于探索和人工分析。

## 4. 任务入口规范

所有生产任务放在 `jobs/`，必须支持命令行运行。

命名建议：

```text
jobs/daily_after_close.py
jobs/build_factors.py
jobs/build_labels.py
jobs/generate_signal_score.py
jobs/run_backtest.py
jobs/generate_order_plan.py
```

命令行参数至少包含：

```text
--trade-date 或 --start-date/--end-date
--operator
--run-id 可选；未传入时自动生成
```

任务入口只负责解析参数、读取配置、调用 `src/` 里的实现、写出产物和日志。

## 5. run_id 与可追踪性

run_id 格式遵循：

```text
任务名_交易日期_运行时间
```

示例：

```text
build_factors_20260707_20260707T184500
generate_order_plan_20260707_20260707T191000
```

以下产物必须包含 `run_id`：

```text
raw 数据
clean 数据
数据质量报告
股票池
因子
标签
打分排名
目标组合
风控报告
计划单
模拟成交
影子持仓
```

## 6. 配置规范

所有可调参数必须放在 `configs/`。

允许的配置来源：

```text
configs/data_sources.yaml
configs/model.yaml
configs/portfolio.yaml
configs/risk_limits.yaml
```

禁止在代码中硬编码：

```text
成交额阈值
持仓数量
单票上限
行业上限
手续费
滑点
因子权重
数据源地址
```

如果代码默认值和配置冲突，以配置为准。

## 7. 数据字段规范

通用字段：

```text
symbol：6 位股票代码
exchange：SH / SZ / BJ
trade_date：YYYY-MM-DD
source：数据来源
run_id：运行批次
update_time：写入时间
```

金额单位：

```text
price：元
amount：元
volume：股；如果数据源给出手，必须转换或在数据说明中标注
```

缺失值规则：

```text
数值缺失使用 null/空值
不要用 0 代表缺失
布尔缺失不得默认视为安全
```

## 8. 因子与标签规范

因子输出长表字段：

```text
symbol
trade_date
factor_name
factor_value
factor_version
source_quality
run_id
update_time
```

因子计算只允许使用 T 日及以前数据。

标签输出字段：

```text
symbol
trade_date
horizon
forward_return
label_version
start_rule
end_rule
run_id
update_time
```

标签可以使用未来价格，但禁止进入 T 日打分和计划单生成。

## 9. 错误处理与默认动作

核心原则：

```text
数据不可信时默认不交易
核心质检失败时阻断计划单
异常必须可定位
```

任务失败时必须输出：

```text
任务名
run_id
异常类型
异常信息
影响产物
是否阻断主链路
```

不要把异常只打印到控制台后继续生成计划单。

## 10. 测试规范

第 1 个月至少建立三类测试：

```text
字段/配置读取测试
因子公式抽样复算测试
主链路冒烟测试
```

冒烟测试目标：

```text
读取样例 clean 数据
生成股票池
生成 5 个因子
生成 10日/20日标签
生成 signal_score
输出 TopN 样例
```

测试文件命名：

```text
tests/test_run_id.py
tests/test_factor_week1.py
tests/test_label_week1.py
tests/test_week1_pipeline_smoke.py
```

## 11. SQL 规范

表名使用小写 snake_case。

字段要求：

```text
主键或唯一键必须明确
关键事实表必须带 source、run_id、update_time
日期字段使用 trade_date/report_period/publish_date 等明确名称
```

不要在 SQL 中嵌入业务阈值，业务阈值放在 `configs/`。

## 12. 提交与评审规范

每次提交应聚焦一个主题：

```text
数据采集
因子实现
标签实现
风控实现
文档规范
```

代码评审至少检查：

```text
是否使用未来数据
字段是否和文档一致
是否带 run_id
是否读取配置
异常是否会默认不交易
是否有最小测试或人工复算说明
```

## 13. 第 1 周落地要求

第 1 周代码规范验收以以下结果为准：

```text
model.yaml 与研究文档因子一致
数据工程产物可被读取
研究文档可转化为因子/标签/打分实现
后续新增 jobs 能按本规范组织
```
