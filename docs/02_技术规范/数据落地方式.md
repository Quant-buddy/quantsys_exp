# 数据落地方式草案

版本：v0.1
状态：待启动会确认  

---

## 1. 推荐方案

第一个月建议采用：

```text
PostgreSQL + Parquet
```

分工：

```text
PostgreSQL：保存核心维表、交易表、计划单、风控结果。
Parquet：保存较大的日线、因子、回测中间结果，可被 DuckDB/Polars 快速读取。
```

---

## 2. 第 1 周简化方案

如果数据库环境还没准备好，第 1 周可以先用 Parquet/CSV 跑通链路：

```text
先跑通样例数据 -> 因子 -> 排名 -> 计划单
第 2 周再补 PostgreSQL 入库
```

但必须保持字段格式与 DDL 一致。

---

## 3. 数据分层

建议沿用四层：

```text
raw：原始接口返回
clean：标准化后的股票、日历、行情、状态、财务、行业
feature：因子、标签、排名
trade：组合、风控、计划单、成交、持仓
```
