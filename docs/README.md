# 文档入口

本文档目录服务于第一个月 MVP 主链路：

```text
免费数据采集 -> 数据清洗与质检 -> 因子/标签 -> 打分排名 -> 组合风控 -> T+1 计划单 -> 影子持仓与日报
```

文档管理原则：

```text
长期有效的规范按领域沉淀。
阶段性的任务、会议、验收按月份和周归档。
岗位文档用于协作推进，但不要让长期规范永远埋在某个岗位目录下。
```

## 1. 新人阅读顺序

第一次进入项目，建议按这个顺序读：

1. `00_架构/量化系统架构.md`：理解系统边界、数据可得性、主链路和目录结构。
2. `01_项目管理/第1个月/第一个月MVP冲刺任务书.md`：理解第一个月要跑通什么、不做什么。
3. `01_项目管理/第1个月/第1周/第1周任务清单.md`：理解第 1 周目标和每天产物。
4. `01_项目管理/第1个月/第1周/第1周任务分配表.md`：理解每个任务的负责人、产物和阻塞关系。
5. `01_项目管理/第1个月/第1周/6个岗位任务卡.md`：按自己岗位查看职责、依赖和完成定义。
6. `00_架构/项目资产说明.md`：查看当前代码、文档、数据文件分别是什么。
7. `03_数据/交付记录/第1周/data_handoff_notes.md`：如果要使用第 1 周样例数据，先读这份交接说明。

## 5. 维护规则

1. 长期规范放在领域目录，不再埋在某一周目录下。
2. 每周过程文档放在 `01_项目管理/第X个月/第Y周/` 或各领域的 `交付记录/第Y周/` 下。
3. 数据交付文档必须能对应到 `data/` 里的数据文件和 `manifest.json`。
4. 技术规范变更时，要同步检查 `configs/`、`jobs/`、`sql/`、`src/` 是否需要更新。
5. 废弃草案不要混在主入口，后续统一放到 `99_归档/`。
